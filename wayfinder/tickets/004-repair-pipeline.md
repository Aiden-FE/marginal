## Question

设计 TXT 导入后的修复流水线，受既定立场约束：章节结构（切分/标题）自动 + 可重跑；正文改动一律 diff 审核制。

需要钉定的决策：

1. 章节切分：纯启发式（正则/统计）与 LLM 辅助的分工边界；切分失败/重跑的交互；超大单章再切分的策略。
2. 正文清洗：乱码/广告/错字修复的建议生成方式；diff 审核的粒度（逐条/按类型批量/整章过一遍）与信任等级设计。
3. 修订（Revision）模型：快照粒度（章/段）、回滚语义（回滚一条 vs 回滚一轮）、重跑修复时与既有修订的关系。
4. AI 任务队列在本流水线的最小形态（本工单只定修复所需的最小队列能力，完整队列在插图工单定）。

产出：修复流水线设计决策（将写入 spec 对应章节）。

## Resolution

（无人值守模式：以下均为 grilling 轮次中给出的推荐答案，经用户授权采纳，可事后否决。）

**1. 章节切分 = 启发式先行 + LLM 兜底**：
- 第一遍纯本地启发式：正则匹配章节标题模式（第X章/卷/回、数字编号、Chapter N 等）+ 统计兜底（空行密度、异常长度段）；每个切分点带**置信度**。
- 仅低置信区间交 LLM 提议边界（把候选区间发给文本任务供应商，要求返回切点+理由）。
- **切分预览界面**是必经环节：树状章节列表 + 拖拽合并/拆分，确认后才应用为结构修订。
- 重跑 = 重新执行整条切分流程，产生**新的**结构修订，不覆盖历史。
- 超大单章（>2 万字）再切分：先启发式找内部小标题/空行密度，再走 LLM 提议切点，同样经预览确认。

**2. 正文清洗 = 结构化建议 + diff 审核制**：
- AI 按类目（乱码 / 广告水印 / 错字 / 其他）输出结构化建议：{锚点, 原文, 建议, 类目, 理由}，不直接改文。
- 审核粒度：按类目批量接受/拒绝 + 逐条查看 diff；整章过一遍的"审校模式"作为第三种入口。
- 信任等级：唯一允许自动应用的是**无语义变化的规范化**（空白清理、编码修复），默认关闭，设置中可开；其余一律 diff 审核（既定立场，不可放宽）。

**3. 修订（Revision）模型**：
- 章级快照 + 结构/内容两类修订：结构修订存切分前后的章节边界快照；内容修订存补丁列表（锚点+原文+替换文+类目+接受状态）。
- 每次"执行修复"产生一个**修复批次（Repair Run，runId）**，其全部修订共享批次号。
- 回滚语义：回滚单条内容修订 = 应用逆补丁；回滚结构修订 = 恢复边界快照；**回滚一轮 = 整批撤销**。
- 重跑修复永远新增修订；修订历史只追加、不改写。

**4. 最小任务队列**：顺序执行（并发 1）；每完成一章即 checkpoint 持久化；状态机 pending/running/done/failed/cancelled；失败章节可单独重试；断点续跑对齐 research/002 结论。

对下游的输入：修订补丁带稳定锚点（段落索引+字符偏移）→ 数据模型工单（005）；切分预览与 diff 审核 UI 进 spec 功能清单。

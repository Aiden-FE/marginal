## Question

v1 的 AI 接入是「用户自配 OpenAI-compatible 端点，浏览器内 fetch」。小程序端受网络层平台约束，要钉死可选项的事实：

1. 域名限制：`wx.request` 的域名白名单（https、需 ICP 备案域名、test 环境可不校验）、是否允许 IP/本地地址、供应链上是否有可绕过的官方通道。
2. 直连自有/第三方 OpenAI-compatible 端点是否可行；不可行则候选路径及其成本/门槛：自建中转服务（用户自己的服务器 + 备案域名）、微信云开发云函数作代理（云函数出网是否受白名单约束）、第三方聚合中转。
3. 流式输出：`wx.request` 的 enableChunked / SSE 支持现状；文本任务（修复/实体提取）流式是否必要。
4. 图片生成在小程序的现实路径：直连不可行的前提下，图片二进制如何往返（中转/云函数拉流再返回 + 落本地文件）。
5. 鉴权与密钥安全：用户 OpenAI 风格的 API Key 放哪里才不泄（本地 storage 明文 vs 云函数环境变量 vs 中转服务）——个人工具与安全的最小平衡。
6. 内容安全：AI 生成内容在小程序有无强制内容安全接口/审核要求（涉及 004 合规）。

产出：网络与 AI 接入路径清单（含每条路线的门槛/成本/体验权衡），供 grilling 工单选型，并标注「需用户定夺」的分叉（尤其收费后端 vs 免费直连）。

## Resolution

（无人值守模式：推荐方案已采纳，可事后否决；见 research/weapp/003）

- **正式版无法「任意自配端点直连」**：request 仅 https+已配置+ICP 备案域名；直连第三方端点在正式版不可行，且 key 放本地会被反编译提取。
- **默认接入 = 微信云开发云函数代理**（callFunction 不走域名白名单；key 存云函数环境变量）；备选 = 自建中转（需备案域名服务器）；开发/体验版 = 勾选「不校验域名」真机即可连任意端点。
- 文本任务可非流式（loading 分段）；要流式用 enableChunked，版本 prototype 实测。
- 图片链路：云函数拉取→base64→落 USER_DATA_PATH 文件→image 本地路径。
- **需用户定夺**：是否接受云开发（按量，免费额度够自用）；是否保留正式发布的 AI 出网能力。

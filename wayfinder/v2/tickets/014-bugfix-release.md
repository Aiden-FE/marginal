## 本次发布内容

修复两处用户反馈的 bug，覆盖阅读器与书架两条产品路径。

### Fix 1：书架阅读进度改为整书加权百分比
- **修改：** `apps/marginal/lib/features/library/library_page.dart` `_progressOf()` 改用 `prefs.workProgressRatio(chapterWeights, chapterIndex, chapterRatio)`，按章节 `wordCount` 加权汇总整书进度；与阅读器 chrome 内部一致。
- **影响：** 书架卡片进度条、百分比文字、「继续阅读」卡片百分比，全部改为整书百分比。
- **测试：** 重写 `library_page_test.dart`「卡片渲染阅读进度条与百分比」用例（c-2/0.42 → 71%）；新增「整书加权：长章权重更高，未读时显示 0%」用例（wordCount [100,300] + c-2/0.5 → 63%）。
- **行为变更：** 多数现有用户的书架百分比会升高（之前永远 ≤ 单章 %，现在 ≤ 整书 %），属修复而非破坏性改动。

### Fix 2：阅读器跨章滑动
- **修改：** `apps/marginal/lib/features/reader/reader_page.dart`
  1. ListView 包 `NotificationListener<ScrollNotification>`，捕获 `OverscrollNotification`，手势内累计 overscroll 达到 viewport × 0.12 触发跨章（一次手势只切一次，到 `ScrollEndNotification` 释放闩锁）。
  2. 章首下拉 → `_open(targetRatio: 1.0)` 切上一章章尾；章末上拉 → `_open(_index + 1)` 切下一章。
  3. `_open` 路径上 `_savePositionNow` 改为 `unawaited` —— 不再阻塞切章 IO。
  4. 新增 `_maybePrefetchNextChapter()`：`_onScroll` 接近真实章末（≤ 1.5 viewport）时预取下一章 projection + window；`_open` 命中缓存则跳过 IO，零等待切章。预取失败不阻塞阅读。
- **测试：** 新增 `reader_page_test.dart` 两条 widget 测试：
  - `overscroll 章首下拉回上一章章尾`
  - `overscroll 章末上拉入下一章开头`
- **保留：** 三分热区 tap 仍是另一条跨章路径，不替换。

## 现象

书架卡片与「继续阅读」卡片显示的阅读进度百分比，是**当前章节的滚动比**，不是**整本书的加权进度**。和阅读器内顶/底 chrome 用的整书百分比不一致。

例：两章书，第二章读到 42% → 书架显示「42%」+ 进度条；用户期望应看到「约 71%」（先读完全部第一章 + 第二章的 42%）。

## 代码路径（已定位）

- `apps/marginal/lib/features/library/library_page.dart`
  - L92–101 `_progressOf(work)`：返回 `(ratio: pos?.ratio ?? 0, finished: isWorkFinished(...))`。`ratio` 直接来自 `loadReadingPosition(work.settings).ratio`——**单章比**。
  - L841 卡片 `LinearProgressIndicator(value: progress.ratio)`。
  - L852 卡片百分比 `'${(progress.ratio * 100).round()}%'`。
  - L973 「继续阅读」卡片百分比同上。
- `apps/marginal/lib/app/reading_prefs.dart`
  - L48–68 `workProgressRatio(chapterWeights, chapterIndex, chapterRatio)`：**整书加权函数已经存在**，阅读器 chrome 用的就是它（`reader_page.dart:481`）。书架侧从未调用过。
  - L95–104 `isWorkFinished(...)`：已用整书判定，无需改。

## 冲突检查（无重复实现）

- 全文 grep `workProgressRatio` 在 `lib/` 下：阅读器侧 1 处，书架侧 0 处。
- `library_page_test.dart:228–274` 测试显式断言「第二本书读到 c-2/0.42 时显示 '42%'」——这正是当前错误行为被测试锁死的源头，需要重写。
- 没有别的「书架整书进度」实现，所以这是 bug，不是 wontfix（已实现）。

## 推荐修复（agent 自定细节）

1. 在 `_LibraryPageState` 里维护 `Map<String, List<int>> _chapterWeightsByWork`（与阅读器的 `_chapterWeights = wordCount > 0 ? wordCount : 1` 同语义）；从已加载的 chapters 计算：
   ```dart
   weightsFor(Work work) {
     final chapters = _chaptersByWork[work.id] ?? const <Chapter>[];
     return [for (final c in chapters) c.wordCount > 0 ? c.wordCount : 1];
   }
   ```
   章节列表已存在（`_chaptersByWork`），无需新增 IO。
2. 改 `_progressOf`：
   ```dart
   final pos = loadReadingPosition(work.settings);
   final chapters = _chaptersByWork[work.id] ?? const <Chapter>[];
   final idx = pos == null ? 0 : chapters.indexWhere((c) => c.id == pos.chapterId);
   final ratio = pos == null
       ? 0.0
       : prefs.workProgressRatio(
           chapterWeights: weightsFor(work),
           chapterIndex: idx < 0 ? 0 : idx,
           chapterRatio: pos.ratio,
         );
   final finished = isWorkFinished(
     positionChapterId: pos?.chapterId,
     positionRatio: pos?.ratio ?? 0,
     chapterIdsInOrder: chapters.map((c) => c.id).toList(),
   );
   return (ratio: ratio, finished: finished);
   ```
3. 重新写 `library_page_test.dart:228–274`：
   - 同一两章用例：把 chapters 的 wordCount 设成 `[100, 100]`，c-2 ratio=0.42 → 期望 `LinearProgressIndicator.value` ≈ 0.71、`'71%'`、`'读完'`（最后一本 99% 不变）。
   - 加测：wordCount `[100, 300]` + c-2 ratio=0.5 → 期望 0.5 + 100/400 * 0.5 = 0.625 → `'63%'`。
   - 加测：未读（无 `reading` 字段）→ `0%`。

## 不变量保护（修时勿踩）

- 顶部「继续阅读」卡片显示的章节名仍应是 `position.chapterId` 对应的章节（`library_page.dart:963` 已有），不要顺手替换成「整书下一章」。
- `isWorkFinished` 阈值 0.98 保持不动。
- 「未读」判定 `library_page.dart:106–109` 用的是 `progress.ratio <= 0.98`，依赖整书后会自动正确，**不要同时改未读阈值**。
- 阅读器 chrome 已用 `workProgressRatio`，改完书架后两端视觉一致；不要求改阅读器。

## 风险

- 行为变更对所有现有用户可见：之前书架百分比虚低（单章百分比永远 ≤100%，整书百分比也会 ≤100%），平均上会**升高**。属于修复，不算破坏性改动，但需要在 release notes 里点一句。
- 如果未来 chapterWeights 用 `wordCount` 但用户重排了章节或改了正文长度，旧 `settings.reading` 里存的 `chapterId` 仍能正确映射，因为 `chapterIndex` 用 `chapters.indexWhere` 实时求。
